# Title/Abstract Rescreening Instructions

**Scoping review:** Generative AI in Introductory Programming Education
**Reviewer:** Beimnet Zenebe
**Purpose of this document:** for title and abstract screening. 

(Document updated before rescreening after the Research Question were updated to the current ones)

---

**The operational test for inclusion:**

> Does the paper describe at least one identifiable use of GenAI in an introductory programming context, **for the benefit of students**, in enough detail to name the activity involved and say something about who performs it?

---

## 1. Screening criteria

Apply at title and abstract level. This stage is liberal. Do not exclude on absence of detail alone unless the abstract makes clear no relevant detail exists.

### Include if ALL of the following hold

| Dimension | Criterion |
|---|---|
| **Population** | Students in an introductory / CS1-equivalent course. Defined by **course level** (first formal programming course), **not student year**. Includes CS0, intro courses for non-majors, intro programming for engineering or science students. |
| **Concept** | **Generative** AI: LLM-based tools, code-generating models, LLM-powered tutors, chatbots, or feedback systems. |
| **Context** | Formal tertiary education, credit-bearing courses. |
| **Beneficiary** | **The student.** The GenAI use must be directed at student learning or student activity. |
| **Deployment** | The GenAI use must have been **deployed with, used by, or observed among students**, or be a reported account of student use. |
| **Date** | 2022 onward |
| **Type** | Empirical studies, experience reports, deployed tool papers, qualitative studies, perception studies where specific student uses are described. Peer-reviewed or preprint both acceptable. |
| **Language** | English. |

### Exclude if ANY of the following hold

| Dimension | Criterion |
|---|---|
| **Population** | Advanced courses, CS2 / data structures, professional developers, K–12, graduate-only cohorts. |
| **Concept** | Non-generative AI only: classic intelligent tutoring systems, ML-based hint systems, traditional autograders, static analysers. |
| **Context** | MOOCs, bootcamps, informal or self-directed learning, workplace training. |
| **Beneficiary** | **Primarily instructor-facing**. |
| **Deployment** | **Tool or system papers with no student deployment**. |
| **Use** | No educational use of GenAI described; no programming activity identifiable. |
| **Type** | Editorials, keynote abstracts, panel summaries, posters or extended abstracts under ~4 pages, **secondary reviews** (systematic reviews, scoping reviews, meta-analyses, mapping studies). |
| **Language** | Not English. |

**Secondary reviews:** exclude from the corpus, but tag them since they are needed for the differentiation argument.

## 2. Pre-decided borderline cases


| Case | Decision | Notes |
|---|---|---|
| **Model capability benchmarks** — e.g. testing GPT-4 or Codex against CS1 exam questions, no students involved | **EXCLUDE** from corpus;  | No student performs an activity; nothing to code for delegation or durability. This is the single biggest change from the earlier screening pass — under the old syntax-barrier framing these looked central. Expect several previously-included records to fall here. |
| **Primarily instructor-facing tools** — LLM-generated feedback for graders, autograding systems, exercise-generation tools for teachers, workload-reduction tools | **EXCLUDE** | The beneficiary is the instructor, not the student. |
| **Mixed-beneficiary papers** — student-facing use is present alongside instructor perspectives or instructor-side tooling | **INCLUDE** | Judge by the **primary** beneficiary. If a student-facing use of GenAI is substantively described, include. |
| **Instructor interview / survey studies** describing how *students* use GenAI, or how instructors plan for student use | **INCLUDE** if specific student uses are described and attributable | Distinguish *who was surveyed* from *who benefits*. Instructors reporting on student AI use is a student-beneficiary paper. Instructors reporting on their own grading tools is not. |
| **Tool papers with no student deployment** — a system is described, built, or demoed but never used with students | **EXCLUDE** | |
| **Pure attitude or perception surveys** about GenAI in general, with no specific use or activity described | **EXCLUDE** | Fails the extractability test — no activity to name. |
| **Papers on over-reliance, self-regulation, metacognition, help-seeking, self-efficacy** in GenAI-using CS1 students | **INCLUDE** | These map to the out-of-frame (metacognitive / affective) dimension in extraction. Excluding them would distort the dimension counts. |
| **Pooled cohorts** — e.g. CS1 and CS2 reported together, or mixed-level intro cohorts | **INCLUDE** provided the authors characterise the whole cohort as **novice** or introductory-level |  so the limitation can be recorded. Exclude only if the pooled cohort clearly includes non-novice populations (e.g. professional developers, advanced students). |
| **Preprint with a later published version** | Include the **published** version; deduplicate the preprint; record the link | |
| **Duplicate records across databases** | Deduplicate; keep one | |
